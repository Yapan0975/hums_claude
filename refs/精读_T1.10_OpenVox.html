1 背景与动机：为什么 instance-level open-vocab voxel 是个硬问题

从 ConceptFusion (RSS 2023)、ConceptGraphs (ICRA 2024) 到 Open-Fusion (ICRA 2024)，open-vocabulary mapping 已经成为主流。OpenVox 想同时拿下三个看似矛盾的目标：(i) 增量实时、(ii) 实例级、(iii) 对前端噪声鲁棒。

1.1 已有路线的两条死胡同

  • point-wise feature 路线（LERF [11]、OpenScene [27]、ConceptFusion [10]）：把 VLM 特征点级投影/蒸馏到 3D 空间——简单高效，但对象边界模糊，无法支持下游"对象级"任务；
  • mask-level + 离线 graph clustering 路线（OpenMask3D [14]、MaskClustering [13]）：用 SAM/instance 模型抽 mask 特征，再跨帧聚类——质量好，但必须离线 batch 处理，不能 online。

1.2 现有 incremental 工作还有两个痛点

  1. 缺 language reasoning：ConceptGraphs [16] / Open-Fusion [18] 都直接用 VLM 特征，对"找一种可以画画的材料"这类常识推理无能为力（VLM 特征本身不具备"推理"能力）；
  2. IoU 关联脆弱：用 3D bbox IoU 或 2D mask IoU 做 cross-frame association，抗不了 missing / under / over segmentation——一旦关联失败，错误会在 incremental 过程里复利累积。
"These methods... exhibit limited robustness to front-end noise, often resulting in association and fusion failures. The core difficulty lies in achieving accurate cross-frame instance association while maintaining the map's ability to recover from noise, under the condition that only the current frame is available." —— §I
🎯 一句话定位
OpenVox = 把"前端：YOLO-World + TAP + SBERT"和"后端：probabilistic instance voxel（Dirichlet-Categorical）+ codebook"组装起来，把跨帧融合显式拆成 MLE（association）+ MAP（map evolution）两个子问题，从而在实时、增量、对前端噪声鲁棒三者间取得平衡。

2 论文的四大贡献

🧊 ① OpenVox 框架

提出 incremental instance-level open-vocabulary mapping 框架，支持 fast & precise 的场景重建与理解。

📝 ② Caption-Powered Instance Understanding

用 LLM（SBERT，384 维）编码 instance captions 而非直接用 CLIP/VLM 特征，增强语言推理能力。

🎲 ③ Probabilistic Instance Voxels

每个 voxel 存一个概率 instance ID 向量 $\theta^j$；把跨帧融合数学地建模为 MLE + MAP 两阶段，adaptation + recovery from noise。

📊 ④ 多数据集 + 真机实验

Replica（8 场景）+ ScanNet（6 场景）：zero-shot instance/semantic segmentation + open-vocab retrieval；Autolabor M1 + RTX 3060 真机部署。

🏆 核心数字成果
  • Replica 平均：AP 11.73（ConceptGraphs 6.01）/ AP50 27.29（12.37）/ AP25 38.46（24.71）；
  • Replica 平均 mIoU 27.30（ConceptFusion 4.68 / ConceptGraphs 16.49 / Open-Fusion 16.45）；mAcc 43.42；
  • ScanNet 平均 mIoU 22.84（vs Open-Fusion 20.91）；mAcc 54.23（vs 49.04）；
  • Retrieval R@1：Ontology 0.905 / Relevance 0.762 / Functionality 0.714（均超 ConceptGraphs 0.810/0.429/0.476）；
  • 体素分辨率 0.04 m；测试 GPU：RTX 4090（onboard 实验为 RTX 3060）。

3 预备：开放词汇地图 vs 闭集语义地图

3.1 闭集语义地图（OpenVox §II.A）

SemanticFusion [5]、Semantic-OcTree [25]、See-CSOM [6]、HD-CCSOM [7] 这类工作——CNN 给固定 K 类的 softmax，CRF/Bayesian update 维护体素级语义。瓶颈：训练时定下的 label set 决定能识别什么，无法泛化到 open-world。

3.2 开放词汇地图（OpenVox §II.B）

  • point-wise：ConceptFusion [10]、OpenScene [27]、LERF [11]；
  • mask-level offline：OpenMask3D [14]、MaskClustering [13]；
  • incremental instance/region：ConceptGraphs [16]、Open-Fusion [18]、OpenGraph [17]、OpenObj [12]；
  • 共同问题：无 language reasoning、IoU 关联脆弱。

3.3 符号约定

符号含义维度
$C_t, D_t, P_t$RGB / 深度 / 位姿（时刻 $t$）image · image · SE(3)
$m_t^i$第 $i$ 个 2D maskimage patch
$f_t^i$mask $i$ 的 caption 特征$\mathbb{R}^{384}$（SBERT）
$V_t = \{v_t^j\}$体素集合（$j$ 是 voxel index）—
$\theta^j = \{\theta^{j,\gamma}\}$voxel $j$ 的概率 instance ID 向量$\sum_\gamma \theta^{j,\gamma}=1$
$B_t = \{f_t^\gamma\}$codebook（实例 $\gamma$ → 融合后的 caption 特征）—
$I_t^i$mask $i$ 关联到的 map instance ID$\in \Gamma_{t-1} \cup \{\text{new}\}$

4 OpenVox 总览：前端流水线 + 后端概率体素

┌────────────────────────────────────────────────────────────┐ │ 输入: RGB C_t, Depth D_t, Pose P_t（实时流） │ └────────────────────────────────────────────────────────────┘ │ ▼ ┌──────────────────────────────────────────────────────┐ │ 前端：Instance Segmentation & Understanding │ │ │ │ YOLO-World (Det) ──> TAP (SegCap) │ │ │ │ │ │ │ ▼ │ │ │ 2D mask m_t^i + caption "..." │ │ │ │ │ │ │ ▼ │ │ │ SBERT (Enc) → f_t^i ∈ R^384 │ └──────────────────────────────────────────────────────┘ │ ▼ {m_t^i, f_t^i}, D_t, P_t ┌──────────────────────────────────────────────────────┐ │ 后端：Probabilistic Voxel Reconstruction │ │ │ │ Step ①: Mask → Voxel projection │ │ V_{m_t^i} = Vox(D_t[u,v]·P_t·K^-1·[u,v]) │ │ │ │ Step ②: Instance Association (MLE) │ │ A = w_geo·S_geo + w_fea·S_fea (公式 8 + 9) │ │ → I_t^i = argmax_γ A_{I_t^i=γ} │ │ │ │ Step ③: Live Map Evolution (MAP, Dirichlet) │ │ α_t^{j,γ} = α_{t-1}^{j,γ} + y_t^{j,γ} (公式 14) │ │ θ_t^{j,γ} = α_t^{j,γ} / Σ_γ α_t^{j,γ} (公式 15) │ │ │ │ Step ④: Codebook Updating │ │ w_t^i = A_{I_t^i} · R_t^i (公式 16-17) │ │ f_t^{I_t^i} = (W·f_{t-1} + w·f_t)/W' (公式 18) │ └──────────────────────────────────────────────────────┘ │ ▼ 全局地图 M_t = {V_t, B_t}：实例级、open-vocab、概率 │ ▼ 推理（render mask / open-vocab query）

4.1 关键模块对应到的方程

  • 前端整体：式 (1) $\{m_t^i, f_t^i\} = \text{Enc}(\text{SegCap}(\text{Det}(C_t)))$；
  • 问题定义：式 (2) $P(I_t, M_t | M_{t-1}, Q_t)$；
  • chain-rule 分解：式 (3)（MLE × MAP）；
  • 关联：式 (4)–(9)；
  • map evolution（Dirichlet）：式 (10)–(15)；
  • codebook update：式 (16)–(19)。

5 前端：实例分割 + LLM caption encoding

OpenVox 的前端做了一个三阶段流水线 Det → SegCap → Enc。亮点在于不用 CLIP 特征，而是先让 TAP 模型把每个 mask 自动写一句 caption（"a wooden cabinet" / "a beige stool"），再用 SBERT 编码成 384 维向量。

5.1 三个组件

组件模型作用
Det(·)YOLO-World [28]real-time open-vocabulary detection（出 bbox）
SegCap(·)TAP [29] (Tokenize Anything via Prompting)用 bbox 作 prompt，出 mask + 描述性 caption
Enc(·)SBERT [8]把 caption 编码为 384 维特征
$$\{m_t^i, f_t^i\} = \mathrm{Enc}\!\left(\mathrm{SegCap}\!\left(\mathrm{Det}(C_t)\right)\right) \tag{1}$$

5.2 为什么不用 CLIP 而用 caption？

🎯 设计动机
"find a material to use for painting" 这类查询需要常识推理，纯 CLIP 特征做不到（CLIP 是 image-text 对齐，没有逻辑推理）。SBERT 编码的 caption 自带语言层面的语义结构，再叠加 LLM 推理通路（论文未明确，但可由下游 LLM 接 codebook 完成）就能实现 ontology / relevance / functionality 三种检索（§13）。

这正是消融数据里 functionality retrieval R@1 = 0.714（vs ConceptGraphs 0.476）的来源——CLIP 特征做不到"花是给恋人的好礼物"这种推理。

6 后端 ① 问题定义与分解（MLE + MAP）

这是 OpenVox 的数学核心——把"既要关联又要更新地图"的联合问题，用 chain rule 拆成两个可单独求解的子任务。

6.1 联合后验

给定当前观测 $Q_t = \{\{m_t^i, f_t^i\}, D_t, P_t\}$ 和上一步地图 $M_{t-1} = \{V_{t-1}, B_{t-1}\}$：

$$P(I_t, M_t \mid M_{t-1}, Q_t) \tag{2}$$

6.2 chain-rule 分解

$$P(I_t, M_t \mid M_{t-1}, Q_t) \;=\; \underbrace{P(I_t \mid M_{t-1}, Q_t)}_{\text{instance association}} \cdot \underbrace{P(M_t \mid M_{t-1}, Q_t, I_t)}_{\text{live map evolution}} \tag{3}$$
💡 为什么这个分解很关键
  • 关联 → MLE：先给 mask 分配 ID（不影响地图状态），数据似然最大化；
  • 更新 → MAP：已知 ID 后，单独更新每个 voxel 的概率向量 + codebook；
  • 两步都有闭式或快速近似解（Dirichlet conjugate prior），适合实时；
  • 错误的关联可以在之后被概率更新自动 dilute——这就是论文反复强调的 "recover from noise"。

7 后端 ② Instance Association（MLE）

7.1 mask 间条件独立

$$P(I_t \mid M_{t-1}, Q_t) = \prod_i P(I_t^i \mid V_{t-1}, B_{t-1}, m_t^i, f_t^i, D_t, P_t) \tag{5}$$

7.2 投影：mask → voxel region

$$V_{m_t^i} = \mathrm{Vox}\!\left(D_t[u,v]\,P_t\,K^{-1}\cdot[u,v] \mid [u,v]\in m_t^i\right) \tag{6}$$

7.3 MLE 公式（uniform prior）

$$P(I_t^i \mid V_{m_t^i}) \propto P(I_t^i)\,P(V_{m_t^i} \mid I_t^i) \tag{7}$$

uniform $P(I_t^i)$ 下化为最大化似然。直接乘 voxel 概率会数值下溢——论文用"累积证据 + 大数定律"，用均值代替乘积：

7.4 几何相似度

$$S_{\,I_t^i = \gamma}^{\text{geo}} = \mathbb{E}_j\!\left(\{\theta_{m_t^i}^{j}[\gamma]\}\right) \tag{8}$$

7.5 特征相似度

$$S_{\,I_t^i = \gamma}^{\text{fea}} = \mathrm{CosSim}\!\left(f_{t-1}^\gamma,\, f_t^i\right) \tag{9}$$

7.6 决策

加权融合 $A_{I_t^i=\gamma} = w_{\text{geo}}S^{\text{geo}} + w_{\text{fea}}S^{\text{fea}}$（论文未明确给出 $w$ 数值——这是论文一个小遗憾，§17 我们会回到）。当 $\max_\gamma A_{I_t^i=\gamma}$ 超过相似度阈值就关联，否则新建实例。

📌 几何 + 特征双通道的妙处
纯几何（IoU）容易被 over/under segmentation 误导；纯特征（CLIP/caption）容易跨实例混淆（"两把外形相似的椅子"）。OpenVox 同时用 voxel-level 概率均值（geo）和 codebook 余弦（fea）做加权——任一通道失误，另一个可以补偿。这是它比 ConceptGraphs 鲁棒的核心原因。

8 后端 ③ Live Map Evolution（Dirichlet-Categorical MAP）

已知 mask 关联到的 $I_t^i$，每个 voxel $v^j$ 的概率向量 $\theta^j$ 怎么更新？OpenVox 借鉴 S-BKI [30] 的 "semantic counting sensor model"，用Dirichlet-Categorical 共轭对给出闭式更新。

8.1 MAP 形式

$$p(\theta_t^j \mid y_t^j) \propto p(y_t^j \mid \theta_t^j)\,p(\theta_t^j) \tag{10}$$

8.2 Categorical likelihood

$$p(y_t^j \mid \theta_t^j) = \prod_{\gamma \in \Gamma}\left(\theta_t^{j,\gamma}\right)^{\,y_t^{j,\gamma}} \tag{11}$$

8.3 Dirichlet conjugate prior（核心！）

$$p(\theta_{t-1}^j) \propto \prod_{\gamma \in \Gamma}\left(\theta_t^{j,\gamma}\right)^{\alpha_{t-1}^{j,\gamma}-1} \tag{12}$$ $$p(\theta_t^j \mid y_t^j) \propto \prod_{\gamma \in \Gamma}\left(\theta_t^{j,\gamma}\right)^{\alpha_t^{j,\gamma}-1} \tag{13}$$

8.4 更新公式（最干净的一步）

$$\boxed{\alpha_t^{j,\gamma} = \alpha_{t-1}^{j,\gamma} + y_t^{j,\gamma}} \tag{14}$$

这就是 "instance counting sensor model" 的全部内容：每次 voxel $v^j$ 被关联到实例 $\gamma$，对应 Dirichlet 参数 $\alpha^{j,\gamma}$ 加 1。

8.5 闭式期望

$$\theta_t^{j,\gamma} = \frac{\alpha_t^{j,\gamma}}{\sum_{\gamma \in \Gamma}\alpha_t^{j,\gamma}} \tag{15}$$
⚠️ 注意这里和 evidential 的微妙差异
OpenVox 的 Dirichlet 参数 $\alpha_t^{j,\gamma}$ 是"类别投票计数"，它的总和 $\sum_\gamma \alpha_t^{j,\gamma}$ 仅作为归一化项，没有显式地承担"我对这个 voxel 有多不确定"的语义。
在 EvidLife-Map（我们的工作）里，同样的 Dirichlet $\alpha$ 总和 $S = \sum_\gamma \alpha_t^{j,\gamma}$ 直接给出 vacuity $u = K/S$，这是 epistemic uncertainty 的标量——我们会用这个标量同时驱动 open-set / loop-closure / map-decay。
所以 OpenVox 已经用了 Dirichlet 的"似然/记数"层面，但放弃了 Dirichlet 的"不确定性"层面。这一点是我们 §17 差异化定位的关键支点。

9 后端 ④ Codebook 加权融合

voxel 存的是"属于谁的概率"，codebook 存的是"实例 $\gamma$ 的语言特征"。codebook 的更新决定了 retrieval 质量。

9.1 观测权重 $w_t^i$

$$w_t^i = A_{I_t^i} \cdot R_t^i \tag{16}$$

9.2 可见率 $R_t^i$

$$R_t^i = \frac{\left|V_{m_t^i}\,\big|\, \arg\max_\gamma \theta_{t-1}^j[\gamma] = I_t^i\right|}{\left|V_{m_t^i}\right|} \tag{17}$$

$R_t^i$ 表示当前 mask 观测的部分占该实例总大小的比例——只看到沙发一角时，权重低，防止用残缺视角污染 codebook。

9.3 加权融合（一阶 EMA）

$$f_t^{I_t^i} = \frac{W_{t-1}^{I_t^i}\, f_{t-1}^{I_t^i} + w_t^i\, f_t^i}{W_t^{I_t^i}} \tag{18}$$ $$W_t^{I_t^i} = W_{t-1}^{I_t^i} + w_t^i \tag{19}$$
📌 这是个相当成熟的设计
"关联概率 × 可见率"作为信任度，再做累加均值——比裸 EMA 多了对"局部观测"的鲁棒性。配合 caption 特征自身的稳定性（SBERT 对不同视角同一物体生成的 caption 高度相似），OpenVox 的 codebook 在 cluttered 真实场景里也能稳。

  • Relevance（"a microwave 找 timer"）R@1 从 0.429 → 0.762（+0.333）——这是论文的"杀手锏"；
  • Functionality（"warm the body 找 ..."）R@1 从 0.476 → 0.714（+0.238）——CLIP 完全做不到的语言推理任务。

论文还展示了 Fig. 6 的定性图：query "gift for lovers" → 检索到花；query "warm the body" → 检索到合理对象。这种 reasoning 能力是 ConceptGraphs 等 CLIP-based 方法天花板。

Autolabor M1 移动机器人 + Azure Kinect (RGB-D) + Livox MID-360 LiDAR SLAM 提供 pose。

💻 算力

🔍 验证 query

"place garbage"、"black water bottle" → 渲染正确高亮。

🎯 真机为什么是论文最大说服力
ConceptGraphs / MaskClustering 都需要 offline batch 处理（论文 §I 反复强调）；OpenVox 是少数能在消费级 GPU + 真实噪声下 online 跑的 open-vocab instance mapping。这是它"卖点"的核心。

15 方法优势与未明确说出的代价

✅ 论文显式声明的优势
  • real-time：相比 ConceptGraphs / OpenMask3D / MaskClustering 的 offline；
  • instance-level：相比 ConceptFusion / Open-Fusion 的 point-/region-level；
  • probabilistic：能 recover from 前端噪声；
  • language reasoning：caption + LLM encoding，支持 relevance / functionality 查询；
  • 消费级 GPU 部署：RTX 3060 onboard。
⚠️ 论文没说但能看到的代价
  • 前端依赖太多模型：YOLO-World + TAP + SBERT 三个，failure mode 复杂；
  • 固定 voxel 分辨率 0.04 m，没有 multi-resolution（与 Schmid 的 panoptic multi-TSDFs 形成对比）；
  • 关联权重 $w_{geo}, w_{fea}$ 论文没给出具体值，相似度阈值也未明确；
  • Dirichlet 总和 $S$ 仅作归一化，放弃了 epistemic uncertainty 信号；
  • 静态场景假设——文末承认 "extend OpenVox to real-time dynamic environments" 是未来工作；
  • codebook 无遗忘机制——长期 lifelong 时旧实例 caption 会污染查询。

16 局限与作者承认的未来工作

16.1 论文 §V 自述

"In the future, we plan to extend OpenVox to real-time dynamic environments, further exploiting probabilistic voxels to drive performance improvements." —— §V

16.2 我们读出来的关键缺口

  1. 无 lifelong 机制：incremental ≠ lifelong。OpenVox 演示的是单次会话内的实时增量，没有讨论"几个月后回到同一场景"如何处理旧地图（panoptic multi-TSDFs T1.12 才有 absent/persistent change detection）；
  2. 无 epistemic uncertainty 输出：Dirichlet 用了，但只用了"加 1 计数"，$u = K/S$ 没出现；
  3. open-vocab 但需要前端 query word 由 YOLO-World 检测：即 OpenVox 的"开放性"受限于 YOLO-World 的训练词汇；
  4. 没有 loop closure：依赖外部 SLAM 出 pose，地图本身无 global 一致性优化；
  5. 没有 dynamic object 处理：移动物体会污染 Dirichlet 计数。

这是 OpenVox 三篇精读里最重要的一节——它就是我们论文的最直接对手，必须诚实给出"为什么不被它碾压"的理由。

17.2 §9 — 与 EvidLife-Map 的关系（技术诚实版，~350 字）

OpenVox（Deng et al., arXiv 2025 / RA-L under review）是 EvidLife-Map 在 RQ2（open-set）方向上最直接的对手，且就方法成熟度而言它已经走得比我们远——instance-level + open-vocabulary + caption-based reasoning，真机部署在 RTX 3060。我们必须承认：如果用户的需求是"在开放词汇 query 下查找语义物体"，OpenVox 几乎是最佳选择。然而 EvidLife-Map 不与之直接竞争，而是在正交方向定位：

(i) 方法学差异：OpenVox 用的是 Dirichlet-Categorical 的Bayesian 计数形式（式 14：$\alpha_t = \alpha_{t-1} + y_t$），其 $\alpha$ 总和 $S$ 仅做归一化、放弃了 vacuity $u = K/S$ 这一 epistemic 信号。EvidLife-Map 用的是同款 Dirichlet 但作为 evidential head，显式输出 $u$，并用同一个标量同时承担 open-set 拒识、loop-closure keyframe 选择和 voxel decay 三项任务——这是 OpenVox 框架内无法表达的。

(ii) open-set vs open-vocabulary 的辩护：OpenVox 的"开放"依赖 YOLO-World 检测词表 + TAP caption，本质上仍受前端模型词汇约束；EvidLife-Map 的"开放"是 closed-set 头 + vacuity 触发拒识，对真正的 OOD 实例（前端模型从未见过）能直接输出 "unknown" 而不是错关联。这是我们必须在 §I 和 §II 强调的不同——OpenVox 不会输出 "I don't know"，它会强行分配 ID。

(iii) Inference 复杂度：OpenVox 每次 association 要算 $|\Gamma| \times$ voxel 均值 + cosine，$|\Gamma|$ 随场景增长无界；EvidLife-Map 是 $K$ 类（如 20），固定常数复杂度。

(iv) 结论：§II 必须给 OpenVox 单独一段 differentiation，明确"我们不卖 open-vocab reasoning，我们卖 evidential lifelong"；§I 的卖点应避开 "open-vocab" 直接对决，转而强调 "vacuity 一标量三用 + lifelong" 这一 OpenVox 无法覆盖的空白。

18 总结与启示

18.1 一句话总结

"OpenVox 把 YOLO-World + TAP + SBERT 的前端流水线与 Dirichlet-Categorical 概率体素的后端串成 real-time、instance-level、open-vocabulary 的增量地图框架，在 Replica/ScanNet 上 zero-shot instance segmentation 与 retrieval 全面碾压 ConceptFusion / ConceptGraphs / Open-Fusion，并在 RTX 3060 真机上验证。"

18.2 三个 takeaway

  1. Dirichlet conjugate prior 是 incremental mapping 的"金属骨架"——OpenVox 用了它的 likelihood-counting 层面，但放弃了 vacuity 层面，恰好给 EvidLife-Map 留出了独占空间；
  2. Caption + SBERT 比 CLIP 更适合做 language reasoning——relevance / functionality 检索 +0.33 / +0.24 R@1 是硬证据；如果未来要扩展 EvidLife-Map 的语言能力，可借鉴这一管线；
  3. "MLE + MAP" 分解的优雅：把 association 和 evolution 解耦，避免联合优化的复杂度——这种"chain rule + 子任务"的范式值得借鉴到 evidential lifelong 框架。
