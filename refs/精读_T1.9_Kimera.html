1 背景：human-like spatial perception 的三大支柱

Kimera 的动机是把"高级场景理解"做齐三件事——这三句话也定义了 SPARK Lab 后续 5 年路线图：

  1. Metric-semantic understanding：几何 + 语义同步在场景中"接地"，不像传统 SLAM 只给几何，也不像 deep 语义分割只给 2D；
  2. 多尺度抽象：从 voxel/mesh → object → place → room → building → city，让 task planning 在合适层级展开；
  3. Static + dynamic + relations：不只 object constellation，还要捕捉人/机器人 agents及其与场景的时空关系。
"Humans are able to form a complex mental model of the environment they move in. This mental model captures geometric and semantic aspects of the scene, describes the environment at multiple levels of abstractions (e.g., objects, rooms, buildings), includes static and dynamic entities and their relations." —— Abstract

1.1 历史脉络

  • 2D 拓扑地图（Kuipers, 1978/2000）→ 层次但 2D；
  • SLAM++ / SemanticFusion / Voxblox → 单层 metric-semantic，无 hierarchy；
  • Armeni et al. 2019 / Kim et al. 2019 → 提出 3D-SG 概念但 需要预先 annotated mesh；
  • Kimera (本文) → 第一个 from sensor data 自动构造完整 5-layer DSG 的系统。

2 论文的四大贡献

① 3D Dynamic Scene Graph 形式化（§2）

5-layer DSG：(1) metric-semantic mesh, (2) objects + agents, (3) places + structures, (4) rooms, (5) building。首次把"agents（人、机器人）"作为一层，并允许 compositional 扩展（neighborhood / city 层）。

② Kimera Spatial Perception Engine（§3）

2 个子系统、6 个核心模块：Kimera-VIO / Mesher / Semantics / PGMO（合称 Kimera-Core）+ Kimera-Humans / Objects / BuildingParser（Kimera-DSG）。所有 Core 模块开源。

③ 大量评测 + uHumans2 数据集发布（§4）

EuRoC + uHumans + 12 个新场景的 uHumans2（含 apartment / office / subway / neighborhood，有人群动态）。在 TX2 嵌入式上跑实时。

④ DSG 应用：层次语义路径规划（§5-6）

用 DSG 的 layered 结构做 A* 路径规划，"building → room → places" 三级，比 volumetric ESDF 上的 A* 快几个数量级。

🏆 与 2020 RSS 版本（Rosinol et al. 2020b）的增量
  • 新增 Kimera-PGMO（loop closure 同时变形 mesh，而非只优化 pose graph）；
  • 实现并测试层次语义路径规划；
  • 更全面 evaluation + 真机数据集；
  • uHumans2 共 12 个新场景（含户外）；
  • 在 Nvidia TX2 上的嵌入式实时性验证。

3 §2 3D Dynamic Scene Graph 形式化

DSG 是一个 layered directed graph：节点是 spatial concept（每个节点带 spatial 坐标和 shape/bbox），边是 spatio-temporal relation。单层室内建筑的 5 层结构如下。

┌──────────────────────────────────────────────────────────────────┐ │ Layer 5: Building │ │ one node per building. attrs: pose, bbox, semantic class │ └──────────────────────────────────────────────────────────────────┘ ▲ contains ┌──────────────────────────────────────────────────────────────────┐ │ Layer 4: Rooms │ │ nodes: kitchen, bedroom, corridor, ... │ │ edges (intra): adjacency (door) │ │ edges (inter): contains places │ └──────────────────────────────────────────────────────────────────┘ ▲ contains ┌──────────────────────────────────────────────────────────────────┐ │ Layer 3: Places + Structures │ │ Places: obstacle-free locations, edges = straight-line reach │ │ Structures: walls / floor / ceiling (the "stuff") │ └──────────────────────────────────────────────────────────────────┘ ▲ nearby ┌──────────────────────────────────────────────────────────────────┐ │ Layer 2: Objects + Agents │ │ Objects: static (chair, desk). attrs: pose, bbox, class │ │ Agents: humans + robots. attrs: pose-graph trajectory, mesh │ └──────────────────────────────────────────────────────────────────┘ ▲ vertices belong-to ┌──────────────────────────────────────────────────────────────────┐ │ Layer 1: Metric-Semantic Mesh │ │ nodes = 3D vertices. attrs: pos, normal, RGB, panoptic label │ │ edges = mesh triangle faces │ └──────────────────────────────────────────────────────────────────┘
🎯 DSG 与 knowledge base 的本质区别
DSG 不是抽象 ontology——每个节点都 spatially grounded（位置 / bounding box）。这让它直接 actionable，可以喂给 motion planner / collision checker，而不只是给 LLM 看。

3.1 Agents 的特殊地位

论文区分两类 Layer 2 节点：

  • Objects：静态。一个 node + pose/bbox/class 即可；
  • Agents（humans, robots）：时变。每个 agent 是一个 pose graph（时间戳 3D pose 序列，边是相对测量）+ shape mesh（SMPL）。

3.2 Compositionality（Remark 2）

DSG 可以加层：building 上面加 level（多层楼）、再加 neighborhood、再加 city。这是 Khronos 后来加"时间维"扩展为 4D-DSG 的理论基础。

4.1 实时性策略

  • Kimera-Core 用 5 个线程：IMU front-end（IMU 速率）/ VIO back-end / Mesher / Semantics / PGMO；
  • per-frame mesh 在 < 20 ms 出，用于 obstacle avoidance；
  • Semantics 慢线程（~0.1 s / keyframe），不影响控制；
  • Kimera-DSG 整体在 mesh build 完后顺序运行（offline），但每个模块可以单独跑实时变种（这正是后来 Hydra 做的事）。

5 §3.1 Kimera-VIO：IMU 预积分 + 固定滞后平滑

实现的是 Forster et al. 2017 的 keyframe-based MAP visual-inertial estimator。本节把关键公式写下来——这是后续所有 SPARK Lab 工作（Hydra/Khronos/Clio）的 VIO 基底。

5.1 IMU 预积分（on-manifold）

令两个连续 keyframe 之间的相对 state 增量为 $\Delta\mathbf{R}_{ij}$（旋转）、$\Delta\mathbf{v}_{ij}$（速度增量）、$\Delta\mathbf{p}_{ij}$（位置增量）。Forster et al. 的预积分把 raw IMU $(\boldsymbol{\omega}, \mathbf{a})$ 在流形上组合为 compact 测量：

$$\Delta\mathbf{R}_{ij} = \prod_{k=i}^{j-1} \mathrm{Exp}\big((\tilde{\boldsymbol{\omega}}_k - \mathbf{b}^g_k) \Delta t\big)$$
$$\Delta\mathbf{v}_{ij} = \sum_{k=i}^{j-1} \Delta\mathbf{R}_{ik}\, (\tilde{\mathbf{a}}_k - \mathbf{b}^a_k)\, \Delta t$$
$$\Delta\mathbf{p}_{ij} = \sum_{k=i}^{j-1} \Big[\Delta\mathbf{v}_{ik}\, \Delta t + \tfrac{1}{2}\Delta\mathbf{R}_{ik}\, (\tilde{\mathbf{a}}_k - \mathbf{b}^a_k)\, \Delta t^2 \Big]$$

这些量与 keyframe 处的状态独立——所以可以离线"压缩"raw IMU 流。前端 ~40 μs / sample。

5.2 视觉前端

  • Shi-Tomasi corner 检测 + Lukas-Kanade 光流跟踪；
  • 左右目立体匹配 + 几何验证（mono 5-point RANSAC / stereo 3-point RANSAC）；
  • DVIO 变种：用 IMU rotation 做 2-point (stereo) / 1-point (mono) RANSAC，在动态场景里更鲁棒；
  • 把 IMU 给的 rotational optical flow 当 LK tracker 的 initial guess。

5.3 后端 factor graph

每个 keyframe 把 preintegrated IMU factor + structureless vision factor 加进 iSAM2（GTSAM 增量求解）。Outlier 处理：先 DLT 三角化 → 把退化点（深度负 / 视差小）和重投影误差大的点剔除 → 再消元。Smoother horizon 之外的状态 marginalize out。

6 §3.2-3.3 Kimera-Mesher + Kimera-Semantics

6.1 Kimera-Mesher

  • Per-frame mesh：在当前 keyframe 上 2D Delaunay 三角化跟踪到的特征 → 用 VIO back-end 给的 3D 估计反投影成 3D mesh，<7 ms；
  • Multi-frame mesh：在 VIO 滑窗内融合 per-frame mesh（去重 + 用最新 VIO 估计更新顶点），~15 ms；
  • 检测到 planar surface 时给 VIO 加 regularity factor，紧耦合 mesh-VIO；
  • Table 3：Multi-frame mesh RMSE ~0.45 m vs Global mesh ~0.40 m（V1_01），但前者快两个数量级。

6.2 Kimera-Semantics

基于 Voxblox 的bundled raycasting扩展，做 3 件事：

  1. 构造 global mesh（TSDF + marching cubes）；
  2. 给 mesh 语义标签：用 2D semseg（实验用 Mask-RCNN），bundled raycast 时沿 ray 累计 label 频率向量，仅在 TSDF truncation distance 内累加（省 compute）；
  3. 每 voxel 用 Bayesian 更新维护"label probability vector"，最后取 argmax 做 mesh vertex label。

7 §3.4 Kimera-PGMO：Pose Graph + Mesh Optimization

这是 IJRR 2021 版相对 2020 RSS 版的重大新增——把 mesh deformation 和 pose graph optimization 合并在同一个 factor graph里，loop closure 一来同时校正轨迹 + 全局 mesh。

7.1 Loop closure 检测

  • DBoW2 + ORB → putative loops；
  • mono 5-point + stereo 3-point RANSAC 做几何 verification；
  • 关键创新：作者不把 DBoW2 调严格，反而让 backend 用 PCM 来抗 outlier——这跟其他 SLAM 系统（ORB-SLAM3, VINS-Mono 拒绝 loop）哲学相反。

7.2 Outlier rejection — Kimera-RPGO 的 PCM 变种

Pairwise Consistent Measurement set Maximization (PCM, Mangelson et al. 2018) 原是多机器人设计；作者改成：

  1. 每个新 loop 先做 odometry consistency check（chi-squared on cycle error）；
  2. 通过后再与已有 loops 两两 pairwise consistency；
  3. 增量地更新 adjacency matrix $A$（不是从头算），保证 online；
  4. 用 Pattabiraman et al. 2015 的 fast max clique 找最大一致 loop 集。

7.3 Pose Graph & Mesh Deformation（Kimera-PGMO，Fig. 8）

构造统一 deformation graph：

  • Pose vertices $X_i$：机器人 pose；
  • Mesh vertices $M_k$：用 octree-based vertex clustering 简化 mesh（voxel size 1-4 m）后得到的代表顶点；
  • Edges：mesh 简化保留的 connectivity（绿色）+ pose-mesh visibility 边（黄色）+ pose graph odometry/loop edges（蓝色）。

对每条 deformation graph 边写一个 factor（local frame 之间的相对约束）。Loop closure 来时，整张 deformation graph 在 GTSAM 中一次性优化，mesh 跟着 pose 变形，没有 de-integration / rebuild。

🎯 RPGO vs PGMO 的取舍（Remark 3）
  • Kimera-RPGO：只优化 pose graph，mesh 不变形；快但 mesh 不一致；
  • Kimera-PGMO：同时变形 mesh，更慢（EuRoC 中 pose graph 14k edges → ~140 ms）但 mesh-pose 一致；
  • 用户根据应用挑选。Hydra 选 PGMO 的子集做 scene graph 整体变形。

8 §3.5 Kimera-Humans：SMPL + pose-graph tracking

把人不仅当点而是当时变 mesh来跟踪。这是 DSG agent layer 的灵魂。

8.1 检测

  • 2D semseg 给出 human pixel mask；
  • 裁剪到 bbox → GraphCMR (Kolotouros et al. 2019b) 从单图回归 SMPL mesh（顶点 + camera 参数）；
  • 用 PnP（Zheng et al. 2013）算 mesh 到 camera 的 6-DoF pose；
  • 从 depth map 拿 pelvis 3D 位置 → 转世界坐标（用 VIO pose）；
  • Dynamic masking：把 human pixel 在 Kimera-Semantics 的 raycast 里只标 free space，不污染静态 mesh。

8.2 跟踪（per-human pose graph）

  1. 每个 human 维护一个 pose graph，节点是 pelvis 时间戳 pose；
  2. 相邻节点用零速先验（permissive noise）做 motion factor；
  3. GraphCMR 检测当 prior factor 加入；
  4. data association：最近欧氏距离 + 一致性检查（joint motion 上界 3 m/s, joint displacement 上界 3 m, beta 参数差异 < 0.1）；
  5. Pose-graph pruning：< 10 节点的 graph 视为虚警删除；
  6. Kimera-RPGO + PCM 优化每个 human 的 trajectory。

9 §3.6-3.7 Kimera-Objects + Kimera-BuildingParser

9.1 Kimera-Objects

  • Unknown shape：提取语义类对应 mesh → PCL Euclidean clustering（距离阈值 = 2× voxel size = 0.1 m）→ centroid + canonical bbox；
  • Known shape（给定 CAD 模型）：
    1. 3D Harris keypoints (radius 0.15 m, NMS thresh $10^{-4}$) on CAD + object mesh；
    2. keypoint matching → 多 outliers；
    3. TEASER++ (Yang et al. 2020) 鲁棒 registration → 6-DoF object pose + bbox。

9.3 Kimera-BuildingParser

Places

用 Voxblox ESDF + Oleynikova et al. (2018) sparse topological graph，节点稀疏采样 free space，边 = 直线 traversability。每个 object/agent 关联到最近 place。

Structures

对 wall / floor / ceiling 直接从 semseg label 提；wall 进一步按 room 切：用带 oriented normal 的 mesh vertex 查找最近 places node，按 $\frac{\mathbf{n} \cdot \mathbf{d}}{\|\mathbf{d}\|^2}$ 加权投票决定 wall vertex 的 room ID。

Rooms

Kimera 的 room detection 是批处理的（这正是 Hydra 改进的地方）：

  1. 切 ceiling 下 0.3 m 的水平 2D ESDF 切片；
  2. truncate 到距离 > 0.2 m → 关闭 door 小开口 → 得 disconnected 2D ESDFs（即 rooms）；
  3. 把 Places node 按其 (x, y) 落入哪个 2D ESDF 标 room；
  4. 剩余未标 nodes 用 majority voting 在拓扑图邻域里迭代。
⚠️ Kimera Room detection 的硬假设
"存在水平 ceiling，且高度已知"——这正是 Hydra 摆脱的假设。对 split-level / multi-floor / 复杂户型，Kimera 的 room detection 会失败（uH2 Apartment precision 68% / recall 61%，AeroAstro 71% / 67%）。

16.3 §4.9 TX2 嵌入式

  • Kimera-VIO 在 MAXN 模式默认参数下满足 real-time；
  • 提供 fast（250 features / 5 s horizon）和 faster（200 features / 4.5 s horizon）配置，分别 85% / 75% keyframe time + 65% / 50% backend time；
  • Kimera-Semantics @ 0.1 m voxel size 在 TX2 上 65.8 ms / update；
  • fast/faster 会拖低 hard sequences (MH_*) 上的 APE，需 trade-off。

19 §9 与 EvidLife-Map 的关系

Kimera 是 SPARK Lab 系列的奠基论文，也是 R2 设计的"概念骨架"。我们需要明确：哪些 Kimera 组件被我们复用、哪些被替代、§II related work 如何定位。

19.1 与 Khronos 的延续关系

Kimera 的 DSG 是静态的——agent layer 的人是时变的，但对象层是 snapshot。Khronos (T1.1) 把 DSG 升级为 4D-DSG，引入 "spatio-temporal entities"：物体可以出现、消失、移动，每个 entity 带 timestamps。Kimera 的 5-layer × 时间扩展 = Khronos 的 4D 表示。EvidLife-Map 的 voxel decay 与 Khronos 的 temporal entity 是互补设计：

  • Khronos 在 entity-level 处理动态（"这把椅子昨天在这，今天在那"）；
  • EvidLife-Map 在 voxel-level 处理 evidence 不确定度（"这个 voxel 100 frame 没被观察，vacuity ↑，应该 decay"）；
  • 结合：vacuity decay 可以 trigger Khronos 的 entity-level "object disappeared" 推断，作为 RQ5 dynamic baseline 的 hybrid 设计。

19.2 复用 / 替代 / 改造的逐模块决策

Kimera 模块EvidLife-Map 决策理由
Kimera-VIO直接复用开源稳定，与 Hydra/Khronos 同源；不是我们创新点
Kimera-RPGO / PGMO复用 PCM outlier + 改造 backendPCM 是 SOTA outlier rejection；我们 §III.M2 vacuity-LC 接在 PCM 之前作为 candidate filter
Kimera-Mesher不用per-frame mesh 我们用 nvblox+Voxfield 替代
Kimera-Semantics部分替代bundled raycasting 思路保留，但 Bayesian label update 升级为 Dirichlet evidential update，并加 vacuity 分量
Kimera-Humans不用本文不做人体跟踪；若 RQ5 需要可用 Khronos 的 dynamic entity 替代
Kimera-Objects (TEASER++ CAD fitting)参考不在本文 scope，但若做 RQ4 lifelong object tracking 可借鉴
Kimera-BuildingParser不用用 Hydra 的 incremental GVD + dilation rooms 替代

19.3 §II related work 中 Kimera 的定位写法

建议 paragraph 写法（约 100 字 + cite）：

"Kimera [Rosinol et al., IJRR'21] established the canonical full-stack 3D Dynamic Scene Graph pipeline from visual-inertial data, comprising VIO, mesh, semantics (via Bayesian update over Voxblox), pose-graph-and-mesh optimization, and a building parser. Its 5-layer DSG (mesh → objects/agents → places/structures → rooms → building) became the de facto representation underlying subsequent online (Hydra [Hughes et al., RSS'22]) and 4D (Khronos [Schmid et al., RSS'24]) extensions. EvidLife-Map builds on the same DSG abstraction but augments Layer 1 from a deterministic semantic label to a Dirichlet evidence vector, enabling a single vacuity scalar to drive open-set detection (Layer 2 unknown nodes), loop-closure triggering (Layer 2 agent comparisons), and lifelong decay (mesh-vertex pruning)—three tasks that Kimera's pipeline currently addresses through three separate modules (PCM, GraphCMR consistency, hand-tuned mask thresholds)."

19.4 IMU 预积分公式我们要不要引

Kimera-VIO 的 IMU 预积分公式（§5.1 我们抄了）是 Forster et al. 2017 的，不是 Kimera 原创。R2 §III.M0 (state estimation) 可以一句话指出 "we adopt Kimera-VIO [Rosinol 2021] with no modification"，不需要重写预积分公式。但如果 reviewer 问"为什么不用 ORB-SLAM3"——答："Kimera-VIO 是 SPARK 系列共享的 VIO，便于与 Hydra/Khronos 等 baseline 公平对比"。

19.5 对 RQ5 Khronos dynamic 的启示

Kimera 已经有了 dynamic masking（pixel 级把人遮掉避免污染静态 mesh）。Khronos 把这个思路扩展到 entity 级。EvidLife-Map 的 vacuity decay 提供了第三个机制：voxel 级。三者互补：

  • Pixel mask（Kimera）：检测期就排除；
  • Entity track（Khronos）：跟踪移动的 known object；
  • Vacuity decay（ours）：unknown / 长期不在的 voxel 自然消亡。

RQ5 baseline 设计：Kimera (no dynamic handling) → Kimera + dynamic mask → Khronos → Khronos + vacuity decay，逐步消融。

💡 一句话定位
Kimera = SPARK Lab MSM 系列的"基类"，定义了 DSG 抽象、VIO 底座、loop closure pipeline，但每一层都是 closed-set + deterministic + offline。EvidLife-Map 不替代 Kimera，而是替换其 Semantics 层为 Dirichlet evidence，把三种独立机制（PCM-LC / Bayesian update / dynamic mask）统一到一个 vacuity 标量——这正是论文的核心 thesis。

20 总结与启示

20.1 一句话总结

"Kimera = 第一个 from-sensor 自动构造 5-layer 3D Dynamic Scene Graph 的 Spatial Perception Engine；6 模块开源（VIO + Mesher + Semantics + PGMO + Humans + Objects + BuildingParser），uHumans2 数据集发布；为 Hydra/Khronos/Clio 等 SPARK Lab 系列开辟了 5 年路线图，也是 EvidLife-Map 的概念骨架与公平对比基底。"

20.2 对 R2 / EvidLife-Map 的关键启示

  1. 5-layer DSG 是 MSM 领域 de facto 抽象——不要重新设计图层，直接接 Kimera/Hydra 既有 layer，只替换其单一组件（Layer 1 的 semantics 模型）；
  2. "三层独立机制"的痛点：Kimera 用 PCM 做 LC outlier、用 Bayesian update 做 label fusion、用 dynamic mask 做动态过滤——三套机制共享同一组 voxel 但完全独立。EvidLife-Map 用 vacuity 标量统一，恰好打中这个痛点；
  3. "Loop closure 不仅修轨迹，更修 mesh + semantics"（§7.4 Neighborhood Acc 62.9% → 93.3%）——我们必须保证 vacuity-LC 触发后同时更新 voxel 浓度（不只是 mesh deformation）；
  4. 层次 path planning 4 个数量级加速提醒我们：DSG 不只是表示，更是任务 enabler——若我们做任何 downstream task（RQ3 traversability planning），用 DSG 层次结构能极大加速；
  5. uHumans2 是 community 标准 benchmark——R2 应该至少在 uH2 Office / Neighborhood 上跑实验，便于与 Kimera/Hydra/Khronos/Clio 直接对比。
