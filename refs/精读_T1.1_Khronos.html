1 背景与问题定位

机器人长期自主需要的不只是"某一帧的世界"，而是"世界在所有时刻的样子"。Khronos 把短期动态（人在走）与长期变化（椅子被挪走）第一次放在同一个数学框架里，并能在笔记本 CPU 上实时跑。

1.1 三派工作各自不够

  • 度量-语义 SLAM（Hydra/Kimera/Voxblox）：假设世界静态，对移动 entity 无能为力；
  • 动态 SLAM（DynaSLAM, Dynablox）：擅长把动点剔除以保护定位，但不重建动态实体也不维护时间线；
  • 变化检测（Panoptic Mapping, POCD, POV-SLAM）：处理长期变化，但默认"机器人不在场时"做对比，缺少在线统一表示。

论文一句话总结现状："the literature currently lacks a unifying approach that can reason over both [short-term and long-term]"（§I）。

1.2 Khronos 想解决的问题

🎯 一句话定位
Khronos 提出 Spatio-temporal Metric-semantic SLAM（SMS） 问题：增量地构建一个稠密的、可被任意时刻查询的 4D（XYZ+时间）度量-语义地图，且要在有限算力下实时运行。

2 三大贡献

📐 ① 形式化 SMS 问题

把"4D 度量-语义 SLAM"写成 MAP：$\arg\max_{O, X} P(O, X | Z, \Phi)$，其中 $O = \{O_i^t\}$ 是所有物体在所有时刻的状态。

🧩 ② 基于片段（fragment）的新分解

提出 latent 变量 $Y_k$（object fragment）— 短时窗内 locally-consistent 的观测集合。把 SMS 分解为 Local + SLAM + Fragment Reconciliation 三部分。

⚙️ ③ Khronos 实时系统

Active Window（异步局部建图）+ Global Optimization（变形图 GNC-TLS）+ Reconciliation（光线哈希做"消失证据"推断）。CPU-only，开源。

📊 ④ 仿真 + 真机评测

TESSE 仿真自建 Apartment / Office 两套数据集（含 SMS 标注）+ Jackal 地面机器人 + Boston Dynamics Spot 四足。

3 问题形式化：SMS 的 MAP 公式

3.1 状态定义

场景由若干物体 $O_i \in O$ 组成（背景 $O_{BG}$ 也算一个静态"物体"）。物体在时刻 $t$ 的状态：

$$O_i^t = \{\Omega_i^t,\ T^t_{WO_i},\ L_i\} \tag{1}$$

其中 $\Omega_i^t$ 是表面，$T^t_{WO_i}$ 是其在世界坐标系下的位姿，$L_i$ 是语义标签。机器人位姿：$X^t = T^t_{WR}$。

3.2 观测模型

机器人在 $t$ 时刻观测视体 $V^t$ 内的物体表面，得到测量 $Z_j^t = \{\Omega_j^t, T^t_{RZ_j}, L_j^t\}$，含噪声 $\eta_O$：

$$Z_j^t \sim O_i^t \oplus \eta_O \quad \text{if } O_i^t \in V^t \tag{4-5}$$

同时还有 SE(3) 上的里程计 $\Phi^t \sim \left(X^{t-1}\right)^{-1} X^t \boxplus \eta_\Phi$ （公式 6）。

3.3 MAP 目标

$$O^\star, X^\star = \arg\max_{O, X} P(O, X | Z, \Phi) \tag{7}$$

问题在于：物体数随时间变化、动态与漂移耦合，朴素地求解需要保留全部历史观测，规模随时间线性爆炸。这就是 Khronos 接下来要分解的对象。

4 核心理论：基于"片段（fragment）"的分解

Khronos 的整个数学骨架都建立在一个直觉上：在短时间窗 $\delta$ 内，状态估计误差与场景变化都很小。基于这一"时空局部一致性"假设，引入 latent 变量 $Y_k$ 来解耦全局复杂依赖。

4.1 时空局部一致性假设

$$\left|\left(\prod_{t'=t-\tau}^{t}\Phi^{t'}\right)\boxminus\left(T^{t-\tau}_{WR}\right)^{-1}T^t_{WR}\right| < \epsilon_s \quad \forall t,\ \forall \tau<\delta \tag{8}$$
$$\left|O_i^t \ominus O_i^{t-\tau}\right| < \epsilon_t \quad \forall t,\ \forall \tau<\delta \tag{9}$$

即：(8) 漂移在短时窗内可忽略；(9) 物体在短时窗内基本不变。这是"局部内一切都干净"的形式化表达。

4.2 引入片段 $Y_k$

定义 $Y_k = \{\Omega_k, T_{RY_k}, L_k\}$ —— 一段时间窗内一组 locally-consistent 的观测合成的"物体快照"。每个真实物体 $O_i$ 是若干 $Y_k$ 的集合。一旦下一帧违反 (8)(9)，就开新片段 $Y_{k+1}$。

4.3 三段式分解

关键推导（论文公式 11→13→15→16）：

$$P(O, X, Y, A | Z, \Phi) = \underbrace{\prod_i P(O_i | \bar Y_i, X)}_{\text{Fragment reconciliation}} \cdot \underbrace{P(X, A | Y, \Phi)}_{\text{SLAM}} \cdot \underbrace{\prod_k P(Y_k | \bar Z_k, \bar \Phi_k)}_{\text{Local estimation}} \tag{16}$$
💡 为什么这个分解是"金句"
  • Local Estimation 只看 $\delta$ 窗口内的观测，独立计算，可异步并行；
  • SLAM 退化成 landmark-based pose graph（fragment 充当 landmark）；
  • Reconciliation 推断"一个物体在两个 fragment 间的真实历史"——本质是"absence-of-evidence vs evidence-of-absence" 问题；
  • 三派之前的工作（dynamic SLAM / change detection / panoptic mapping）都是这个分解的特例。

6 模块 1：Active Window（局部估计）

每个 RGBD 帧到达后，Active Window 在 $\delta$ 时窗内做三件事：背景 TSDF 融合、动态点检测、对 mask 进行片段关联与更新。完成后，将"过窗"的片段送到 Global Optimization。

6.1 背景重建

静态背景 $\Omega_{BG}$ 用多分辨率 TSDF + mesh 表示，projective TSDF fusion 增量构建。设计上"任何 surface 表示都能塞进 $\Omega$"——意味着可以替换为 Gaussian Splatting、surfel 等。

6.2 候选观测的获取

每帧的观测 $Z_j^t = \{\Omega_j^t, T^t_{RZ_j}, L_j^t\}$ 来自两个 cue：

  1. 语义/实例分割掩码（默认用 OneFormer，闭集；可换 SAM+CLIP 做开集，§VI-C）；
  2. 几何运动检测：基于 Dynablox [43] 的"落入先前自由空间的点必动"逻辑，但因为 $\delta$ 短，丢掉 Dynablox 的 Occupancy / Sensor Sparsity / State Estimation 三项。

6.3 多假设跟踪与片段抽取

核心数据结构是"候选片段池 $\hat Y$"。算法贪心地把 $Z_j^t$ 关联到 $\hat Y_k$：

  • 关联打分：用 grid-aligned voxel filter 算 $Z_j^t$ 与 $\hat Y_k$ 的 volumetric IoU；
  • 语义 $Z_j^t$ 关联到同 label 的 $\hat Y_k$；动态 $Z_j^t$ 关联到最近的动态 $\hat Y_k$；允许语义-动态交叉关联；
  • 未关联 → 新增 $\hat Y_k$；过窗 → 从池里移除；
  • 有效性过滤：丢弃观测 $< \tau_Z = 15$ 次的、动态位移 $< \tau_D = 1\ \text{m}$ 的候选；
  • 合格者 marginalize 对应观测 $\bar Z_k$，输出片段 $Y_k$ 到全局优化。
💡 表示自由度
"this gives an enormous freedom in choosing suitable representations depending on the task and computation power at hand" —— 静态物体表面用自适应分辨率 TSDF → mesh，动态/可变形物体用点云序列。Khronos 的因子化设计本身不绑表示。

7 模块 2：Global Optimization（变形图 + GNC-TLS）

7.1 变形图构造

沿用 Hughes et al. [16] 的 deformation graph，但增广上 fragment 位姿节点 $T_{WY_k}$：

  • 观测边 $E_{obs}$ = $E_{XX} \cup E_{P_M P_M} \cup E_{XP_M} \cup E_{XY}$ —— 机器人位姿、mesh 控制点、机器人–控制点、机器人–片段；
  • 候选边 $E_{can}$ = $E_{YY} \cup E_{LC}$ —— fragment 关联 + loop closures；
  • $E_{YY}$ 候选：同 label（开集时取 cos sim）+ bounding box 有交叠的 fragment 对；当前仅建模为纯平移约束（centroid 对齐），6DoF 配准留作未来。

7.2 鲁棒位姿图优化

$$\begin{aligned}T^\star = \arg\min_{T_1,\dots,T_n \in T,\ \omega_{ij}\in\{0,1\}}\ &\sum_{(i,j)\in E_{obs}}\|T_i^{-1}T_j \boxminus \bar T_{ij}\|^2_{\Lambda_{ij}}\\&+ \sum_{(i,j)\in E_{can}}\left(\omega_{ij}\|T_i^{-1}T_j \boxminus \bar T_{ij}\|^2_{\Lambda_{ij}} + (1-\omega_{ij})\bar c^2\right)\end{aligned} \tag{17}$$

用 Truncated Least Squares (TLS) 把每条候选边的 inlier/outlier 用二元变量 $\omega_{ij}$ 显式建模，求解器是 GNC [54] + GTSAM [9]。$E_{YY}$ 边的协方差仅保留平移项（旋转方向取零，$\lambda = 1$ permissive）。

7.3 输出

  • 机器人位姿 $X^\star$ 全部更新；
  • 片段位姿 $T^\star_{WY_k}$ 全部更新；
  • $\omega_{ij}$ 标识 fragment 关联与 loop closure 是否被采纳；
  • 背景 mesh 通过 mesh 控制点 $P_M^\star$ 做 as-rigid-as-possible deformation。

8 模块 3：Reconciliation（可变形变化检测）

Fragment 只编码"我看到 X 在这里"（positive evidence），不直接告诉我们"X 在 $t$ 时刻不在了"。Reconciliation 用光线几何来推断 absence。

8.1 核心想法：光线哈希库

每当一个背景 vertex $p_v$ 在 Active Window 中固化下来，记录一条"代表光线"：$(p_v, p_r)$，其中 $p_r$ 是观测窗中点的机器人位置。把这条光线塞进一个粗分辨率全局哈希表（key 是 vertex / view 的格子索引）。机器人和背景在格子内可自由变动，超大变动（如 loop closure）时整表重算。

8.2 几何判据

对一个 fragment 表面上的查询点 $p_q$，遍历哈希返回的候选光线 $(p_v, p_r)$：

$$d_r = \frac{\|(p_q - p_r) \times (p_r - p_v)\|}{\|p_q - p_r\|},\quad d_d = \frac{(p_q - p_r) \cdot (p_v - p_r)}{\|p_q - p_r\|} \tag{18-19}$$
  • $d_d \gg \|p_v - p_r\|$：$p_q$ 被遮挡（occlusion）；
  • $|d_d - \|p_v - p_r\|| < d_{ray} = 30\ \text{cm}$：geometric consistency（"东西还在"）；
  • $d_d < \|p_v - p_r\|$：evidence of absence（"光线本该穿过它"）。

稳定阈值：$\tau_{ray} = 5$ s 时窗内 $c_{ray} = 60\%$ 的光线报告 absence 才采纳。

8.3 时间区间推断

对每个 fragment $Y_k$，计算"首次观测前最近的 absence"和"出窗后最早的 absence"，配合 evidence-of-presence 的边界，假设 object 在窗内"以均匀概率出现/消失"，最小期望误差估计就是窗中点。这给出每个物体的 $[\text{appear}, \text{disappear}]$ 区间。

🔑 设计精妙之处
Khronos 没有显式维护"自由空间体素图"——那会随时间线性增长且变形成本高。它用稀疏的光线库 + 全局哈希近似全局自由空间信息，并自然地"跟着机器人位姿一起变形"。

10.2 评测指标

对 4 类实体（background / static object / dynamic object / change）各算 Precision / Recall / F1。背景按"20 cm 内有 GT vertex 算正样本"；物体按"有对应 GT object 算正样本"；变化按"label 一致（appeared/disappeared）"。

4D-metric：对所有机器人时刻 $T$ 与信念时刻 $t \leq T$ 求二重积分：

$$L_{4D} = \frac{1}{2T^2}\int_0^T \int_0^T L\left(M^T(t)\right)\,dt\,dT \tag{20}$$

10.3 基线

"目前没有 real-time dense metric-semantic spatio-temporal SLAM"，所以分别对比子任务专长方法：

  • Hydra [16]：全局一致的 metric-semantic perception；
  • Dynablox [43]：稠密建图 + 动态物体检测；
  • Panoptic Mapping [42]：在线长期一致 volumetric mapping。

硬件：Intel i7-12700H 笔记本 + 32 GB RAM（CPU-only），TSDF 分辨率 $\nu = 8\ \text{cm}$，传感范围 $r = 5\ \text{m}$。

Khronos 的关键时序数字（§VI-F）：

  • Active Window：常数复杂度，45.5 ± 9.2 ms / 帧，即22.2 FPS；
  • Fragment 重建（从 active window 出窗）：偶有 spike，但通常 < 1 s；
  • 背景 deformation：随观测体积线性，通常 < 1 s；
  • 位姿图优化（GNC-TLS）：仅当 loop closure 时触发，最坏几秒；
  • Reconciliation：ray hash 从头重算时是 worst case；inference + reconciliation < 100 ms。

所有重计算都在独立线程跑，所以在线运行不会因偶发 spike 卡帧。

13 作者声明的局限

✅ 强项
  • 第一个同时实时处理短期 + 长期的 metric-semantic SLAM；
  • CPU-only，机器人可部署；
  • 开放集 / 闭集语义前端都能接；
  • 提供新的 4D-metric 评估方法。
⚠️ 局限（§VII）
  • Fragment 关联只用 bounding-box centroid，对部分观测/遮挡敏感；缺 6DoF 配准；
  • Fragment 仅几何关联，"被搬动的物体"无法关联到原 fragment——缺 fragment descriptor；
  • Reconciliation 假定有 reference surface，在大开阔空间或稀疏表面下退化；
  • 所有 fragment 都常驻内存，问题规模无限增长——理想做法是边缘化"过时或 confidently reconciled" 的 fragment 以支持 lifelong；
  • 动态检测依赖 Dynablox-style 自由空间 cue，靠近相机沿相机方向运动的人检测不到。

14 ⭐ 与我们 EvidLife-Map 的关系（RQ5 主战场）⭐

Khronos 是 RQ5（"动态场景下的 lifelong 时空建图"）我们要在表里直接拉一行对比的对手。这里我们要诚实地拆解：哪些是 Khronos 已经赢的、哪些是 Khronos 没解决的、我们如何差异化定位。

14.1 方法关系：互补 + 部分竞争

🎯 总判定
Khronos vs EvidLife-Map = "factor-graph 4D SMS" vs "Dirichlet evidential lifelong MSM"。
Khronos 是显式因子化时空的路线；EvidLife-Map 是每体素带证据强度 + vacuity的路线。两者的建模哲学完全正交——Khronos 把"时间维"显式做成 fragment + reconciliation 推断；EvidLife-Map 不显式建时间维，而是用vacuity 衰减隐式编码"这个体素的证据多久前来的"。

14.2 我们引用它的理由

  • §II Related Work：作为"dynamic + long-term MSM"的代表，与 Panoptic Mapping、Dynablox 并列；
  • §III Problem Formulation：Khronos 的 SMS 定义是我们 lifelong 部分的"完美参照系"——我们要明确我们的 problem 与 SMS 的形式化差异（见 14.5）；
  • §IV-D Voxel Decay：Khronos 承认 fragment 内存无限增长是其局限，EvidLife-Map 的 vacuity-decay-driven marginalization 直接是这个限制的答案——这是我们 voxel decay 模块最核心的"卖点 vs Khronos"。

14.3 实验对手：如何在 RQ5 表里跑头对头

  • baseline 实现策略：用作者开源 (https://github.com/MIT-SPARK/Khronos)，不自己重写。但论文 Tab. I 的数字是在 TESSE Apartment / Office 自建数据上跑的——我们不重跑 TESSE 数字，而是在我们的 lifelong 数据集（自录或公开如 ScanNet++ / Replica-Khronos-style）上重跑双方；
  • 公平性：给 Khronos 同样的 RGBD + 里程计 + 语义前端（OneFormer 或 我们的 evidential head 的 argmax）。语义前端在两个方法上保持一致；
  • RQ5 评测指标：4D F1（沿用 Khronos 的 $L_{4D}$）+ 我们额外的"vacuity-aware change F1"（对带 vacuity 的预测做 calibration aware 评分）；
  • 会出现的失败模式（要诚实写）：在"短窗内大量同类动态物体（多人乱走）"场景，Khronos 的 multi-hypothesis tracker 会比我们 evidential aggregation 略强 —— 因为它显式做关联，而我们靠 vacuity；这点要诚实承认。

14.4 它的哪些设计可以借鉴

  1. "时空局部一致性"的形式化（公式 8-9）—— 我们 §III 也需要在 vacuity-decay 模块前面做一个"短窗内 evidence 可信"的假设陈述，可以直接 cite Khronos 公式 (8)(9) 作为先行工作；
  2. GNC-TLS 鲁棒 PGO—— 我们 loop closure 的 RQ4 用到，可以 cite 同样的 GNC + GTSAM 工具链；
  3. $L_{4D}$ 评测协议—— 我们的 RQ5 lifelong 实验直接复用，省去自创指标的争议；
  4. 分离 active window / global / reconciliation 的三层架构—— 我们的 evidential aggregation / decay / OOD 三个 stream 在时序上也是异构频率，可以借鉴 Khronos 的"独立线程 + spike 不卡帧"工程实现。

14.5 我们 §III 需要明确 differentiate 的点

差异化定位（要写进 §III.B 与 §IV.D）
  1. 时间的处理方式：Khronos 显式存"片段时间戳 + 区间推断"；EvidLife-Map 用Dirichlet vacuity 的单调衰减隐式编码时间，体素老化 ≡ vacuity ↑ ≡ 边缘化触发器。我们不维护 fragment 数据结构，因此没有 Khronos 的内存爆炸问题（这是我们 RQ4 的优势）；
  2. 不确定性建模：Khronos 用 truncated least squares + binary outlier weights 处理关联不确定；EvidLife-Map 用evidential Dirichlet 把所有不确定（OOD / 老化 / 类间冲突）统一到一个 vacuity 标量，进而 (i) 触发 RQ2 open-set；(ii) 通过熵通道用于 RQ3 loop closure 描述子；(iii) 触发 RQ4 衰减——一标量三用途；
  3. 语义后端：Khronos 默认闭集 OneFormer，开放集是 SAM+CLIP 拼接；EvidLife-Map 用原生 evidential head 输出 Dirichlet 浓度 $\alpha$，open-set 检测是模型一阶能力而非外挂；
  4. 变化检测机制：Khronos 用光线哈希做 evidence-of-absence（依赖 reference surface）；EvidLife-Map 用vacuity 上升 + Dirichlet 浓度衰减—— 在大开阔空间 / 稀疏表面 也能工作（这是 Khronos 自认的局限）；
  5. Lifelong 性：Khronos 自承"problem keeps growing indefinitely"；EvidLife-Map 的衰减机制天然 garbage-collect 老体素，内存常数复杂度。
⚠️ 不要装腔作势
  • Khronos 在"短期动态物体的实例分割与跟踪"上做得比我们扎实——它有显式的 multi-hypothesis tracker；我们的 evidential 聚合是被动的；
  • Khronos 的 $L_{4D}$ 指标是它定义的，我们沿用相当于站在它的评估框架内 — 必须坦诚承认这一"基础设施贡献"；
  • Khronos 已 open-source、有真机验证（Jackal + Spot），系统成熟度是我们目前比不上的——我们的优势必须建立在"理论统一 + lifelong 内存有界"两点上，而不是 "我们比 Khronos 更全"。

15 总结与启示

15.1 一句话

Khronos 通过引入 "object fragment" 作为时空局部一致性的 latent 变量，把 4D 度量-语义 SLAM 因子化为 Local + SLAM + Reconciliation 三个解耦子问题，并在 CPU 上实时实现，是当前同类工作中最接近一统短期/长期动态的统一框架。

15.2 给 EvidLife-Map 的 5 个具体行动项

  1. §II Related Work 必须用一整段比较 Khronos —— 不能只在表里出现；
  2. §III.A 引用 Khronos 公式 (8)(9) 作为"短时一致性"假设的前置工作；
  3. §IV.D Voxel Decay 必须在写"为什么 vacuity-decay" 时明确反驳 Khronos 的"无限内存增长"局限；
  4. §V RQ5 用作者开源代码跑头对头，不重跑 TESSE 数字，在我们自己的 lifelong 数据集上 evaluate；
  5. §V.E 评估指标用 Khronos 的 $L_{4D}$（公式 20）作为主指标之一，加我们自定义的 vacuity-aware change F1。
