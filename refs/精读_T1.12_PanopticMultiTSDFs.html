1 背景：为什么"长时一致 + 多分辨率"是个硬问题

这是 Lukas Schmid（同时是 Khronos T1.1 一作、HKUST/MIT 教职）的早期重要工作（ICRA 2022），是Khronos 之前的"lifelong + change detection"基础。理解它，就理解了 Khronos 的来路。

1.1 已有三类工作都不够

  • Dense Semantic Mapping（SemanticFusion [4], Voxblox 系 [2][8][9]，PanopticFusion [3]）：把 CNN 语义融进 TSDF，但假设静态环境；
  • Object-centric Mapping（SLAM++[17], Fusion++[18], MaskFusion[7], MID-Fusion[13]）：每个对象一个 TSDF，但只重建选定对象，背景被忽略，不支持 planning；
  • Change Detection（Finman[21], Fehr[23], Langer[24]）：能找出变化，但 post-hoc + 计算重，不适合 online。

1.2 Online Long-term Mapping 也有缺陷

  • Krajník [25]、Lázaro [26]、Tang [27]、Macenski [28] 等：能 online 更新，但缺 volumetric / semantic 表达，且更新粒度是 voxel/grid level，导致变化时留下"碎片"伪影。
"A limitation of these approaches is that they lack the expressiveness, i.e. volumetric and semantic information, needed for robot interaction and do not provide semantic consistency when accounting for changes, thus leaving undesirable artifacts in the map." —— §II.D

1.3 核心 insight

💡 论文 §III 开篇的世界观
"The world typically does not change at random but in a semantically consistent way."
因此变化的最小单位不应该是 voxel，而应该是 object。Schmid 用 panoptic segmentation 把世界分成 (i) 物体实例 (ii) 背景类别 (iii) free space，每个都成为一个独立 submap。"change" 发生在 submap 级别 → 整个物体一起被增/删，避免碎片。

2 论文的三大贡献

🗺️ ① Panoptic Multi-TSDFs

提出 novel flexible multi-resolution volumetric map representation，能capture long-term object-level scene changes。

🔄 ② Integration & Management

给出 panoptic multi-TSDF 的online integration + map management 算法，确保 temporally consistent mapping。

🧪 ③ Sim + Real evaluation

在 flat dataset（自己造，开源）+ RIO 真实数据 上充分评估。Source code + 数据集 open-source。

🌐 Open source

github.com/ethz-asl/panoptic_mapping —— 之后的 Khronos 等工作的代码基础。

🏆 核心数字成果
  • Multi-resolution：与 [36] 同质量，memory ↓ ×23（high resolution 区间）；
  • Long-term consistency：第 2 次运行从前一次地图出发时，accuracy 稳定在 ~1.4 cm（discretization level）；Long-term Fusion [26] 因缺语义一致性会留"碎片"；
  • 真机帧率：i7-8550U @1.80GHz（CPU only，无 GPU）—— flat 5-6 FPS（GT seg）/ 5-7 FPS（Detectron2）；RIO 21-32 FPS；
  • 分辨率范围：$\nu_{small} \in \{2,...,4\}$ cm（小物体）；$\nu_{large} \in \{5,...,10\}$ cm（大物体）；$\nu_{freespace} = 30$ cm；
  • Map 查询时延：130 submap collection 上 3 μs / query。

3 预备：TSDF、submap、panoptic segmentation

3.1 TSDF（Truncated Signed Distance Field）

每 voxel 存到最近表面的 signed distance（正在表面外 / 负在表面内），并截断 $|s| < \delta$。优势：能融合多帧、能 represent free space、能用 Marching Cubes 出 mesh。Voxblox [2] 是经典实现。

3.2 Submap

把大地图切成若干小 TSDF block 集合 → 各自维护各自的 pose & geometry → 利于 SLAM 回环、并行处理、对象级管理。代表工作：Voxgraph [11]。

3.3 Panoptic segmentation [10]

融合 instance segmentation 和 semantic segmentation：每个像素既有 instance ID（thing 类）又有 semantic class（stuff 类）。是本工作的"输入"——论文用 Detectron2 [33] 直接出 panoptic，不做模型优化。

3.4 三类 panoptic 标签

类别例子体素分辨率语义性
Object instances（things）chair, sofa, table2-10 cm（按类自适应）实例级
Background classes（stuff）floor, wall, ceiling5-10 cm（类级）类别级
Free space—30 cm（固定）无语义

5 Map Representation：submap 层级结构

Fig. 3 显示的层级（top → bottom）：

  1. Submap collection：最高层，含 spatial index（用于大场景常数时间查询）；
  2. Submap：含 panoptic / instance / class label、变换矩阵、tracking data；
  3. Bounding sphere：submap 的包围球，用于快速遍历；
  4. Blocks：按 TSDF 标准切分，只为 surface voxel 所在 block 分配（free space submap 例外，需全分配）；
  5. Voxels：dense grid，存 TSDF 值 + belonging probability。

5.1 active vs inactive submap

  • active：当前正在追踪 + 持续融合的；
  • inactive：之前观测的，frozen，但可被 change detection 改变状态。

5.2 按类自适应 $\nu$

💡 multi-resolution 的核心做法
不同于 [5][13][18] 用固定 grid size，Schmid 让 $\nu$ 按 detection 的 class label 选择：
  • $\nu_{small} \in \{2, 3, 4\}$ cm：小/精细物体（杯子、手机）；
  • $\nu_{large} \in \{5, 6, ..., 10\}$ cm：大物体（沙发、墙壁）；
  • $\nu_{freespace} = 30$ cm（固定）；
"高分辨率只放在需要的地方"——这就是 multi-resolution 的语义化解。

论文还强调："all submaps are fully data-parallel"——可分布到多核 CPU。Tab. I 的 5-6 FPS 就是 CPU only 跑出来的（i7-8550U，没有 GPU）。

6 Label Tracking：IoU 关联 + 时间窗滤波

6.1 关联流程

  1. 对每个 active submap：用 Marching Cubes [34] 增量算 iso-surface；
  2. 所有 view frustum 内的 active submap iso-surface 投影到 image plane；
  3. 渲染深度 $z$ 与测量深度 $D$ 差距 $|z - D| < \xi_d = \nu$ 算 valid；
  4. 对每个 input segment：找 IoU 最大 + 同类别的 submap；
  5. $\text{IoU} > \xi_{IoU} = 0.1$ → 关联；否则新建 submap。

6.2 时间窗

  • $\tau_{new} = 3$：新 submap 需追踪 3 帧才"成熟"，否则丢弃 → 避免 false positive；
  • $\tau_{active} = 5$：失踪 5 帧后 deactivate → 防止数据被污染。
📌 与 OpenVox 的微妙差异
OpenVox 用 voxel 概率均值 + cosine 做 association；Schmid 用 iso-surface 渲染 + image IoU——后者计算更重，但对 occlusion 更稳。这是 ICRA 2022 时代的"工程权衡"。

7 Integration：TSDF + belonging probability

7.1 TSDF 权重（公式 1）

$$w_{in}(v) = \frac{f_x f_y \nu^2}{z(v)^4} \tag{1}$$

$f_x, f_y$ 是焦距，$z(v)$ 是 voxel 在 image 中的深度。注意 $\nu^2$ 在分子——大 voxel 权重大，与 voxblox [2] 形式一致。

7.2 Belonging probability $P_b(v)$

每个 voxel $v$ 还有一个"是否属于本 submap"的概率 $P_b(v)$。论文不直接用 CNN softmax（"network probabilities can be overconfident [5,18]"），而是数 "label 匹配的帧数 / 总观测帧数"：

$$P_b^*(v) = \frac{1}{|F_t|}\sum_{f=1}^{|F_t|} \mathbb{I}\{\text{label}(u_f(v)) = \text{label}(S(v))\} \tag{2}$$

7.3 高效近似（核心工程巧思）

$$P_b(v) = \frac{\sum_{f=1}^{|F_t|} p(|F_t| - f)\, \mathbb{I}\{\text{label}(u_f(v)) = \text{label}(S(v))\}}{\sum_{f=1}^{|F_t|} p(|F_t| - f)} \tag{3}$$ $$p(f) = 1/2^{\lfloor f / 128 \rfloor} \tag{4}$$
💡 (公式 4) 的妙处
$p(f) = 1/2^{\lfloor f/128 \rfloor}$ 是个按 128 帧分段的衰减权——越近期权重越大。配合分子分母都是几何级数，整个 $P_b(v)$ 可以用 16 bit 高效增量存储。这是论文一个非常工程性的设计。

7.4 Block pruning

不含相关信息的 block 被剪枝：$\nexists v$ 使得 $|sdf(v)| < \delta \wedge P_b(v) > 0.5$。这保证内存只用在 surface 附近。

8 Map Management：change detection 三态机

8.1 三种状态

每个 inactive submap 有 change state $C(S) \in \{persistent, unobserved, absent\}$。

8.2 比较两个 submap

对参考 submap 的 iso-surface 点 $p \in P$，在另一个 submap 中插值得 $sdf(p)$ 和 weight $w(p)$。三种结果：

  • $|sdf(p)| < \xi_{sdf}$：matching（同表面）；
  • $sdf(p) < -\xi_{sdf}$：与 object map 冲突；
  • $sdf(p) > \xi_{sdf}$：与 free space map 冲突（→ absent 候选）。

8.3 联合权重（公式 5）

$$\hat{w}(p) = \sqrt{\min\!\left(\frac{w(p)}{\xi_w},\, 1\right) \cdot \min\!\left(\frac{w_{ref}(p)}{\xi_w},\, 1\right)} \tag{5}$$

$\xi_w = 100$。$\hat{w}$ 是两个 submap weight 的几何平均，capped 在 1。

8.4 决策阈值

weight-adjusted 同意/冲突点数超过 $\tau_{abs} = 20$ 或 $\tau_{rel} = 2\%|P|$ → submap 被标 matching 或 conflicting。

8.5 状态转换

触发状态变化
inactive submap 与任意 active submap 冲突→ absent
inactive 与任意 active 匹配→ persistent
far back in time, 无重叠观测→ unobserved
active deactivate 时与 inactive 同类 submap 匹配→ 融合（fuse together，重用旧数据）
🎯 关键设计：错误可以纠正
"this way, erroneous matches or rejections, e.g. through sensing noise, are corrected for later on. Far back in time submaps are unknown, and can become absent or persistent again when observed." —— §III.D
三态机不是 once-and-for-all 的——unknown → persistent / absent 可双向转换。

9 Spatio-temporal Queries

Map 查询使用层级 + 时间优先级：

  1. 找 query point $p$ 所在的 submap 和 block（spatial index）；
  2. 若 active submap 命中 → 用最高分辨率；
  3. 否则取所有 persistent submap 的最小 sdf；
  4. 若都不命中 → 查 free space submap；
  5. 仍不命中 → 查 unobserved submap 作"预测"；
  6. 只有 present（active 或 persistent）submap 参与评估指标。

Fig. 7 显示：在 130 个 submap 的 collection 上，查询平均仅 3 μs。是非常快的。

10 实验 A：multi-resolution（Fig. 5）

10.1 设置

Flat dataset（论文自造、开源）：基于 [12] 的 high-fidelity 仿真，2 条轨迹，包含 8 个移动 + 5 个新增 + 4 个移除的物体。

10.2 对比

  • Voxblox [2]：经典 TSDF；
  • Supereight 2 [19]：octree-based；
  • Vespa [36] (adaptive-res octree)：sensor-based multi-res；
  • Ours (GT seg)：用 ground-truth 分割（capability 上限）；
  • Ours (Detectron2)：用 raw Detectron2（实际 robust 测试）。

10.3 关键结果

📊 数字
  • GT seg vs Supereight 低分辨率：相似 memory，error 几乎减半；
  • GT seg vs [36] 高分辨率：同质量，memory ↓ ×23；
  • Detectron2 (naive)：即使分割有误（少检测 + 假阳性增 memory），仍比 baseline 节省 memory；
  • 整体趋势："semantically informed multi-resolution > purely geometric multi-resolution"。

11 实验 B：long-term temporal consistency（Fig. 6）

11.1 设置

Flat dataset 第 2 次运行，从第 1 次的 prior map 出发。对比：

  • Monolithic (continue)：基于 [3][8][9] 风格，直接在原图上继续融合；
  • Monolithic (from scratch)：第 2 次从空白开始；
  • Long-term fusion [26]：voxel 距离更新 > 5 cm 则覆盖；
  • Ours (GT) + Ours (Detectron)。

统一 $\nu = 5$ cm（公平比较）。

11.2 关键结果

🎯 三个观察
  1. Ours 的 reconstruction 误差稳定在 ~1.4 cm（discretization level） —— 即"完美级别"；
  2. Monolithic (continue) 不抓变化，误差高且不降；
  3. Long-term fusion [26] 能降误差，但语义不一致导致"碎片"，误差降不下来 discretization；
  4. Ours 通过包含 matching 的旧数据，coverage 增长显著快于 from-scratch；
  5. GT vs Detectron 差距小，证明对 imperfect segmentation 鲁棒（"only assumes semantic consistency of each submap"）。

11.3 Fig. 1 的核心定性

Fig. 1 是论文最直观的图：左边 monolithic map 留下"红色 ghost"（旧物体不消失）；右边 panoptic multi-TSDFs 干净地把 persistent / absent 用 solid / shaded 区分。这是"submap 是变化最小单位"的视觉证明。

12 实验 C：RIO 真实数据

12.1 设置

RIO dataset [35]（"3d object instance re-localization in changing indoor environments"）：scan 466（2 runs）和 scan 27（4 runs）。用 ground truth pose 或优化 pose。

调整 $\xi_{sdf} = 2\nu$（因为传感器噪声更大），$\tau_{new} = 1$，其他不变。

12.2 结果（Fig. 8, 9）

  • 第 1 次运行：各方法误差相近；
  • 第 2+ 次运行：
    • monolithic (with map)：高 coverage 但含旧数据 ghost（overestimate）；
    • monolithic (from scratch)：低 coverage；
    • Ours：与 from-scratch 质量相当，coverage 显著更大；
  • Fig. 8 定性：(a) 没 prior map → 完整重建，(b) 有 prior → 缺片 + 合并物体伪影；(c)(d) Ours → 干净 + 个体保留。
📌 论文坦诚的限制
"Detectron2 detections" 比 GT 更少 + 更碎，所以 Ours (Detectron) 的 mesh 看起来更 noisy（Fig. 8(d)）。但仍展示了 system 对 imperfect segmentation 的鲁棒性。

14 方法优势与代价

✅ 论文显式声明的优势
  • 真正 lifelong（long-term）：support 多次 session、change detection 双向（unknown ↔ persistent/absent）；
  • multi-resolution 内生：按类自适应 $\nu$，memory 大幅节省；
  • object-level 变化粒度：避免 voxel 级"碎片"伪影；
  • CPU only 实时（5-30 FPS on i7）；
  • 对 imperfect seg 鲁棒：用 Detectron2 raw 输出仍能跑；
  • 3 μs / query 的 spatio-temporal lookup；
  • 开源 + 数据集开源。
⚠️ 论文没说但能看到的代价
  • 不处理 open-vocab：依赖 Detectron2 的 panoptic 类（COCO 类集）；
  • 无 evidential 或 epistemic uncertainty：用 $P_b(v)$ 但作为"belonging count"，非 epistemic；
  • change detection 是 binary 三态：没有"不太确定"的中间态；
  • 无 dynamic object：明确把 short-term dynamics 留给 [5][6][7][13]；
  • submap 间无 loop closure 优化："left for future work"；
  • 关联用 iso-surface render + IoU 计算重（70 ms / frame for tracking）；
  • 无 instance retrieval / language query（仅 geometric + semantic class）；
  • fusion 触发依赖类匹配：分类错就不融合。

15 局限与未来工作（§V）

"In future work, our approach can be readily combined with methods for segmentation refinement and to also account for short-term dynamics. Recognition and re-localization of changed objects could further boost performance." —— §V

15.1 三条 future works

  1. segmentation refinement：与 [3][4][7][8][13][14] 结合；
  2. short-term dynamics：物体跟踪 [5]-[7][13] —— 这正是后来 Khronos (T1.1) 走的路；
  3. changed object re-localization：检测+重定位变化物体 → boost performance。

15.2 我们读出来的关键缺口

  • uncertainty 仅作 belonging probability，无 epistemic：$P_b(v)$ 是 frequency count，不是真正的 "I don't know"；
  • change detection 是 categorical（persistent/absent/unobserved），不是连续的：错过了"渐变 confidence"；
  • fusion 依赖 IoU + class match 双条件：脆弱；
  • $\tau_{new}=3, \tau_{active}=5$ 是 hand-tuned：不同场景需重调；
  • 无 voxel-level decay：只有 submap-level 状态变化。这是 EvidLife-Map §III.M3 voxel decay 想补的空白。

16.2 §9 — 与 EvidLife-Map 的关系（技术诚实版，~330 字）

Panoptic Multi-TSDFs（Schmid et al., ICRA 2022）是 Schmid 在 Khronos（T1.1）之前的 lifelong 工作；从代码上看，github.com/ethz-asl/panoptic_mapping 也是 Khronos 的代码祖先。它是 EvidLife-Map 在 RQ4（lifelong）方向上必须明确 differentiate 的"前传"。三个核心差异：

(i) 变化粒度：Schmid 用 submap 作为变化最小单位，整个物体一起进入 persistent/absent；这避免了 voxel 级碎片，但代价是丢失"局部变化"（沙发上换个抱枕无法表达）。EvidLife-Map §III.M3 用 voxel-level decay，同一 submap 内不同 voxel 可以有不同衰减速率——细粒度但需控制噪声。我们必须在论文中坦言："Schmid 的 object-level granularity 在 robotic interaction（"哪个物体不见了"）上更直接；我们的 voxel-level 在 incremental fidelity（"沙发缺了一角"）上更细"。

(ii) 多分辨率 vs 单分辨率：Schmid 按类自适应 $\nu \in [2, 10]$ cm，memory ↓ ×23 是硬数据。EvidLife-Map 用 single-resolution——必须诚实写明 "single-resolution simplifies the vacuity decay but at higher memory cost; multi-resolution evidential decay is left as future work"。这是 Schmid 对我们的真实威胁，要正面回应。

(iii) 哲学差异：Schmid 的 long-term consistency 是显式优化（三态机 + SDF 阈值）；EvidLife-Map 是隐式驱动（vacuity 升高自动衰减）。前者可调可控但 hand-tuned；后者无超参一致但需 evidential head 训练好。这是 design philosophy 差异，没有谁更优。

(iv) $P_b(v)$ vs vacuity：Schmid 已经用了 16-bit "weighted frequency count"做"voxel-belongingness"，这形式上与 vacuity 接近但语义不同——$P_b$ 是 "voxel 属于这个 submap 的频次"，vacuity 是 "voxel 类别预测的 epistemic 不确定性"。Reviewer 可能混淆，需明确划分。

17 总结与启示

17.1 一句话总结

"Panoptic Multi-TSDFs 把 panoptic segmentation 作为 governing factor，让 submap 成为变化最小单位 + 让 $\nu$ 按类自适应，从而在 CPU only 的 i7 上实现 5-30 FPS 的 multi-resolution 长时一致 volumetric mapping，相对 Supereight memory ↓ ×23 且 reconstruction 误差稳定在 ~1.4 cm 的 discretization level。"

17.2 三个 takeaway

  1. "semantic 是组织 geometry 的最佳手段" —— Schmid 把这一点用 multi-resolution 与 submap-as-change-unit 两个角度落地；
  2. "object-level change detection 比 voxel-level 干净" —— 我们的 voxel decay 必须在 figure 上证明能 match 或超越；
  3. "frequency count + 16-bit 编码" 是非常优雅的 lifelong 内存设计 —— EvidLife-Map 在做 vacuity 存储时可借鉴。
